# Explore HCP Terraform without another account

You can learn the hosted-platform concepts here without signing up for HCP Terraform. We'll use local simulations, then practise a real AWS workflow with the connection you already have.

## 2023 vs 2026

| Remember as Terraform Cloud | What to practise |
| --- | --- |
| Hosted runs and shared state | Workspaces, projects and team access |
| One variable page | Variable sets, run triggers and execution choices |
| A generic policy failure | The framework's enforcement and override rules |

**3-Year Catch-Up:** The exam includes HCP Terraform even if you usually run Terraform locally. You won't need an HCP organization, workspace, login, token or paid service here. The SNS lab runs locally against your selected AWS account.

<a id="runs" />
## Ask how a run starts and where it executes

A **CLI-driven** workflow starts through a local Terraform CLI using the platform integration. A **VCS-driven** workflow starts from source-control events. An **API-driven** workflow starts through platform API calls. These tell you how the run begins, not where it executes.

With **remote** execution, Terraform runs in the hosted environment. With **local** execution, it runs on your machine while using the platform's applicable state and service integration. An **agent** runs jobs on connected infrastructure, which helps when resources are private. Check the Terraform version and credentials in the chosen execution environment.

A speculative plan previews a change, often for a pull request, without being an applyable production change. A normal run can include planning, checks and approval before apply. The sandbox lets you explore these choices locally; it doesn't create a hosted run.

<a id="governance" />
## Choose who can act and which policies apply

Team permissions control who can read, plan, apply or administer resources. A private registry helps teams reuse reviewed modules and providers. Run history and state versions help explain earlier changes; health and drift features check whether infrastructure still matches expectations. You'll still need to handle state and credentials carefully.

Sentinel uses advisory, soft-mandatory and hard-mandatory enforcement. OPA uses advisory and mandatory. Advisory failures report a result without stopping the run. Blocking failures need a fix or an authorized override, where the framework, policy-set settings and permissions allow one. Check those details before assuming a user can override a policy.

Try changing the framework and enforcement level in Governance & Hierarchy Sandbox. All organizations, projects, workspaces and policies shown there are local examples.

<a id="projects" />
## Group workspaces without merging their state

A workspace holds configuration and run settings, variables, state and history. A project groups workspaces for organization and access. Choose workspace boundaries that make ownership and dependencies clear; grouping them into a project doesn't combine their state.

Variable sets share values with workspaces in their configured scope, including project or organization scope. A sensitive mark controls display and access; it doesn't guarantee that Terraform omits the value from state. Remote runs also need credentials in their own environment. Your local AWS profile isn't automatically uploaded.

Run triggers can queue a dependent workspace after an upstream apply succeeds. They don't merge states or automatically turn outputs into inputs. Decide how those workspaces will share the values they need.

## Connect the concepts to your local lab

For a real HCP integration, `terraform login` obtains platform credentials, and a `cloud` block connects the CLI workflow to an organization and workspace. Recognize these for the exam; they aren't prerequisites for this course and aren't in the SNS configuration.

Compare the examples: a pull request requests a speculative plan, a CLI command starts a remote run, or an API integration uploads configuration and queues a run. In each case, check the execution mode and where credentials are available.

For your AWS challenge, review and apply a local SNS plan, grade the topic and its ownership, then destroy it and verify cleanup. You're practising the same review-and-check habit without claiming to have completed a hosted HCP run.
