# Terraform course blueprint verification

Reviewed on 14 November 2026 against all nine pages of [Refresher Course Blueprint.pdf](<Refresher Course Blueprint.pdf>) and the primary sources linked below.

**Verdict: the course is feasible and its eight-domain structure matches Associate 004. Apply the corrections below before implementation.** The PDF is a product specification, not evidence that the runtime, labs, or validators work. The workspace initially contained only the 371,700-byte PDF. There was no application, Terraform configuration, test suite, Git repository, or applicable `AGENTS.md`. `pdfinfo` confirms nine A4 pages; all nine were extracted with `pdftotext -layout`. Page nine was also visually inspected to distinguish PDF layout from executable YAML.

Source PDF SHA-256: `be07ed8d0610a9691e9ae5bd30fa128ecb30d9f834dc3b6704e2ab91467b4e50`.

The host is ARM64. Docker Compose reports `v2.24.3-desktop.1`; daemon availability and image builds have not been tested. No AWS credentials were read, and no AWS or HCP infrastructure was queried or changed during this review.

Implementation and live evidence gathered after this specification review are tracked separately in [docs/VERIFICATION.md](docs/VERIFICATION.md). Historical statements below describe the initial workspace.

## Confirmed baseline

- Associate 004 tests Terraform 1.12. The official page lists a one-hour exam, two-year credential validity, and $70.50 USD before local taxes and fees, without a free retake. Pinning **1.12.2** is a course reproducibility choice; the official requirement specifies the minor version. [Exam details](https://developer.hashicorp.com/certifications/terraform-associate).
- The eight domains contain **37 sub-objectives**. The official change list highlights dependencies/lifecycle, custom conditions, ephemeral/write-only handling, and workspaces/projects. The course must retain Vault coverage within 4h. AWS is the lab platform; AWS-specific knowledge is not required for the exam. [Official content mapping](https://developer.hashicorp.com/terraform/tutorials/certification-004/associate-review-004).
- True/false, single-answer, and multiple-answer formats are appropriate. Multiple-answer prompts specify how many selections to make. [Official sample formats](https://developer.hashicorp.com/terraform/tutorials/certification-004/associate-questions-004).
- Native S3 locking is opt-in through `use_lockfile = true`; DynamoDB locking is deprecated. Include lock-object read/write/delete permissions and bucket versioning. [S3 backend](https://developer.hashicorp.com/terraform/language/backend/s3).

## Coverage gaps to close while preserving the blueprint

Explicitly author resource-versus-data examples, all five complex type families, tuple/set distinctions, Vault secret delivery, postconditions, `removed` blocks, and safe state surgery. Several appear in prose but have no concrete lab assertion in the PDF. HCP lessons also need collaboration, private registry, teams/RBAC, health/drift, policy behavior, variable sets, run triggers, execution modes, and speculative plans. Every objective receives a lesson anchor, checkpoint, and question-bank coverage; practical and conceptual evidence are distinguished in the coverage file.

## Confirmed user requirement for AWS access

At course startup, the application must accept either a provided AWS CLI profile or IAM access keys. The build plan now specifies both onboarding paths, optional session-token support, identity verification, consistent credential selection across local tools, and session-only handling of entered keys. This user requirement supplements the PDF's profile-mount design; both methods are implemented; see the current verification ledger for live coverage.

## Confirmed user requirement removing HCP access

The user explicitly removed the HCP organization dependency during implementation. Domain 08 now teaches HCP concepts through local simulations and performs its SNS lab through the normal local AWS connection. No HCP login, organization, workspace, user token, OIDC bootstrap, or remote-run verification is required. The former remote integration findings describe the original PDF; they no longer define implementation acceptance.

## Runtime finding for scoped check data sources

The live domain-04 test on Terraform 1.12.2 produced detailed plan exit code 2 with zero managed-resource changes because the check block's scoped data source was scheduled for a read. HCL contracts, check statuses, actual secret/artifact comparison and resource ownership all passed. Its idempotency gate now requires a receipt-bound saved plan with no managed-resource or root-output changes, permitting those check data reads. Other labs retain the strict exit-code-0 check. The original test attempt was destroyed and its inventory verified absent before the corrected test.
